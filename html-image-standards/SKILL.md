# HTML 报告配图规范(html-image-standards)

> 来源:2026-11-06 VLM 周报出刊后连续两轮返工——用户先反馈「**报告不够图文并茂**」(补满 38 张图),随后又指出「**要保证图像和内容有关系**」(逐图审计换掉 3 张误配)。本规范把这两次教训固化为出刊前必过的两道关,**以后凡卡片式 HTML 报告都要注意**。

## 0. 何时使用

生成任何「卡片流」形态的 HTML 报告:产业简报/周报/月报、测试报告、版本对比报告、模型分析报告——内容按卡片或条目组织、可以配图的页面。

不适用:纯文字文档、纯代码说明、流程图为主的工程文档(图即内容本身)。

**判断标准:一张卡如果存在「与它讲的事直接对应的图」而没放,就是违规;放了但图讲的不是这件事,同样违规。**

---

## 第一关 · 图文并茂(占位图清零)

设计阶段就要规划三层实图,而不是先出纯文字版再「有空补图」:

| 层 | 规格 | 取图 |
|---|---|---|
| 头部卡/Top 封面 | 640px 宽, quality 76 | 该条目对应文章/样本的第 1 张可用图 |
| 主线/章节横幅 | 900px 宽, quality 74(CSS `aspect-ratio:16/6;object-fit:cover`) | 代表作文章的**第 2 张起**(第 1 张常已被封面占用) |
| 条目缩略图 | 264px 宽(2x retina), quality 70 | 每张卡的图,配 `.thumb img{width:100%;height:100%;object-fit:cover}` |
| 深读插图 `deepfig` | 640px 宽, quality 74,每小节 ≤1 张 | 卡片深读块各小节对应文章段落处的图(正文位置+VLM 双重审计),图注带「(原文图)」 |

- **base64 内嵌**,单文件离线可看;总预算 ~1.1MB(VLM 周报 2026-11-06 期 41 张图实测 1105KB,含深读插图)。
- 单图失败链:同文章第 2–5 张 → 关联文章(同主题)的图 → **才允许**设计化占位,且占位数要压到个位数;命中率 100% 是常态目标(28/28 + 5/5 实测可达)。
- 取图前先判宽度 ≥260px(微信 CDN 常给 140px 小图);webp/gif 一律 PIL 转 JPEG(gif 取首帧)。
- 同一文章的图被两处槽位引用时,后一处 skip_first,避免同图重复。

### 注入机械(按位置插入必翻车,用标记/锚点)

- 封面:生成 HTML 时写 `<!--IMG:key-->` 占位,配图就绪后一轮 `replace`(绝不要按行号/位置插——曾因此吞过 body 标签返工三轮)。
- 缩略图:每卡占位图用**唯一 emoji** 当 key,regex 整块替换 `<div class="thumb"><div class="noimg">…</div></div>` → `<div class="thumb"><img src=…></div>`。
- 横幅:按第 N 个 `<div class="chain">` 依次前插(N = 主线序号)。
- 换图(审计后替换):旧 base64 在文件中唯一,`raw.replace(old_b64, new_b64)` 直换。

## 第二关 · 图-文相关性(VLM 逐图审计)

**「文章里有图」≠「图和这条卡片讲的是同一件事」。** 首图经常是表情包、影视梗、文章开头的反面铺垫图、或「△AI制图」装饰图。出刊前必须:

1. **VLM 独立描述**:全部内嵌图逐张缩到 512px 交给一个可用的视觉模型（使用你有权调用的视觉模型，配置和凭据留在本机）,prompt:「一句话(40字内):这张图里具体是什么?图表/截图/产品照/示意图/表情包?主体与可见文字?」。**不告诉它卡片内容**,防止顺着预期编。
2. **比对**:把描述与每张卡的标题/摘要比对,判「命中/存疑/误配」。
3. **换图(误配槽位)**:用**图片在正文中的位置上下文**选替换候选——把文章 HTML 按 `<img>` 切段,打印每张图前后各 ~60 字正文,选「紧跟主题句」的那张(例:ApolloWorld 文中,开头是「真实路测困境」的铺垫图,紧贴「跑一天抵三年」论断的才是虚拟城市画面)。
4. **候选复验**:新图再送 VLM 描述一次,确认后 `replace` 注入。

### 已踩过的坑(直接当检查表)

- 表情包/梗图冒充内容图(Orilo 卡首图是黑白猫「well well well」表情包 → 换产品场景照)
- 影视截图冒充流程图(主线「RSI 与安全」横幅 → 换漏洞研究流程图)
- 文章的**反面铺垫图**冒充主题图(真实路测困境图 ≠ 世界模型虚拟画面)
- 标注「△AI制图」「△图片由AI生成」的图是装饰,不能当内容图
- 图说(「图说:…」)紧跟在 `<img>` 之后——**先查图说再判断**,一张「体育馆观众席」照片可能恰好就是正文讲的那段 AI 生成视频本身

### 审计自身的技术坑

- 审计 URL 要**复现当初的选图逻辑**(如「第一张 ≥260px」),不是字面上的第一张 URL——否则审错图、报假警。
- 查「无重复图」必须比对**完整 base64**;前 ~300 字符相同只是同 CDN 同编码参数的 JPEG 头同构,不是重复。

## 校验清单(两关全过后才出刊)

```text
① HTML 标签配平(HTMLParser 栈校验)
② 卡片数 / nav 覆盖数 / 分类小计一致
③ 四层配图逐张清点(封面 N + 横幅 N + 缩略图 N + 深读插图 N = 总数),占位 div = 0
④ 完整 base64 无重复
⑤ VLM 审计记录留存(每张图的描述 vs 卡片主题,误配处理结果)
⑥ 链接密度、总大小 ≤ ~1MB
```
